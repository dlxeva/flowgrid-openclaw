# Creator Project Demo

这是比赛演示使用的最小样例项目。

## 场景

用户准备做一个关于 AI 协作方式升级的分享，目标用户是已经使用过 AI 工具、但还没有形成项目化协作方法的人。

OpenClaw 作为工作入口，FlowGrid 作为本地项目状态层。

## 用户原始输入示例

```text
我想做一个关于 AI 协作方式升级的分享。
目标用户是已经用过 AI 工具，但还没有形成项目化协作方法的人。
我希望这个分享能讲清楚为什么普通提示词工作流会丢状态，为什么项目化账本和决策日志很重要。
先帮我梳理定位、痛点、核心结构和下一步。
```

## 期望 OpenClaw 行为

OpenClaw 应该：

1. 判断这是一个新的知识工作项目。
2. 调用 FlowGrid 初始化项目。
3. 和用户自然讨论项目目标、目标用户、表达结构、风险和下一步。
4. 保存原始 session。
5. 调用 FlowGrid closeout。
6. 展示候选决策和下一步动作。
7. 等用户确认后执行 review 和 merge。
8. 在新会话中恢复项目状态。

## 可展示的候选决策

示例：

- 项目定位为面向 AI 深度使用者的协作方法分享
- 核心痛点聚焦在项目状态断裂和决策链丢失
- 第一版结构采用痛点、方法、demo、可迁移框架
- 后续优先制作真实项目示例，而不是先写抽象理论

## 可展示的风险

- 内容容易变成泛泛 AI 教程
- 用户可能无法理解本地项目账本的价值
- demo 如果缺少文件变化证据，会显得像普通聊天总结

## 可展示的下一步

- 完成分享大纲
- 生成第一版 demo session
- closeout 并写入决策日志
- 用新会话恢复项目状态

## 演示验证点

- `.flg/sessions/` 里存在原始输入
- `.flg/patches/` 里存在 closeout patch
- `DECISIONS.md` 出现经用户确认的决策
- `PROGRESS.md` 出现会话进展
- `flg handoff` 能输出当前项目状态
